How this works

          

            

              
Provisioning. Each runtime is an official portable build downloaded straight into your DevKit root on the persistent drive — no installer, no admin. After its first install the SHA-256 hash is pinned in manifest.json, and re-running never touches what's already there (idempotent). “Provision all” installs whatever is missing; per-runtime Reinstall force-refreshes one.

            

            

              
Using them while coding. Put the launchers folder on your PATH, then call tools from anywhere:


:: cmd
set PATH=I:\Apps\DevKit\bin;%PATH%

# pwsh
$env:PATH = "I:\Apps\DevKit\bin;$env:PATH"

              
node · npm · bun · git · python · pip · code all resolve to the portable copies. In VS Code, add this to your settings.json so its integrated terminal inherits them:


"terminal.integrated.env.windows": {
  "PATH": "I:\\Apps\\DevKit\\bin;${env:PATH}"
}

              
Package caches (npm, pip) already live on I:, so installs survive session wipes and re-hydrate fast. Launching code from bin\ also wires your GitHub credentials into VS Code's terminal (GIT_CONFIG_GLOBAL), so git push works out of the box once you've signed in on the GitHub page.

One-time setup (about 2 minutes). SalsaDevKit needs an OAuth App to talk to GitHub. Create it once under your account and paste the Client ID — it's stored on this machine only.

              
    
                
  1. Open github.com/settings/developers
    2. 
                
  2. New OAuth App → name: anything (e.g. “SalsaDevKit”), callback URL: http://127.0.0.1:8465/callback, no client secret needed
    3. 
                
  3. Copy the Client ID, paste it below — and if you entered a different callback URL when creating the app, paste that too (it must match exactly)
    4.
